# Offline runtime verification, 29 September 2026

These checks supersede the earlier forwarding-only test report. They used the owned product 3562 charger running firmware 5.794. Private raw captures and site-specific configuration remain outside this repository.

- With ordinary cloud forwarding disabled, HTTP Fast, Eco, Eco+ and Stop requests were confirmed by fresh device telemetry. Local keepalives continued without upstream sends.
- A 90-second server shutdown followed by restart recovered local telemetry and control using the persisted session. This was not a physical charger reboot or a live cold handshake.
- Manual boost (1 kWh), smart boost (2 kWh, 06:45), and cancellation received native acknowledgements; refreshed configuration matched the targets.
- An inactive timer was changed and read back. All four original timers were restored and read back, preserving unrelated native configuration.
- A restoration request timed out once. The API correctly reported failure; it did not claim success or automatically retry a potentially applied write. A subsequent explicit restoration was verified.
- Desktop and mobile dashboard checks showed live grid/charger power, reported mode, four editable timers, no login, no overflow and no JavaScript errors. Simulated pending/stale observations verified that requested mode is not displayed as device state.
- MQTT Fast and Stop commands were confirmed from device telemetry with forwarding disabled.
- Home Assistant discovered the mode select, both diagnostics and grid/charger power sensors. Discovery remains enabled on the running installation.

The actual firmware emulator also passes local handshake states 1→2→5→6, all four mode handlers, keepalives without configuration mutation, boost parameter handling and native configuration installation. Network, hardware and EEPROM calls are stubbed. A physical cold reboot into a newly negotiated offline session remains unverified.

Firmware forwarding is disabled. Software policy and UDP loopback tests check silent rejection by default and byte-preserving passthrough after explicit opt-in. No firmware update was attempted on the physical charger.
