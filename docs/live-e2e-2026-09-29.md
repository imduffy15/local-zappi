# Live dashboard, MQTT and forwarding checks

> Historical report from before offline runtime integration. See [current architecture](architecture.md) and [later offline verification](offline-e2e-2026-09-29.md) for the subsequent implementation.

Tested against the owned charger on 29 September 2026 with the deployed `b16b946` runtime. These tests send real commands; they are separate from software tests and firmware emulation.

## Dashboard and HTTP

The dashboard opens without an access key. It shows reported mode, four mode buttons and request feedback. Debug panels, disabled placeholder controls and login are removed. Remote status and control endpoints no longer require a bearer token.

Desktop and 390-pixel mobile browser checks passed without JavaScript errors or horizontal overflow. A pending Fast request leaves the displayed mode at Stopped until device readback changes it. Stale telemetry shows Unavailable. Live browser clicks for Eco, Eco+ and Stop were each confirmed by fresh charger telemetry, approximately two seconds after transmission.

## MQTT and Home Assistant

Home Assistant discovered the Local Zappi charging-mode select alongside the existing diagnostic entities. Its Fast service action produced an MQTT request, a charger transmission on the next poll, and matching device telemetry about two seconds after transmission. Home Assistant then showed Fast. A direct MQTT Stop request was also confirmed by the charger and displayed in Home Assistant.

The subscriber received 419 messages across state, events, availability, Ethernet and UDP telemetry topics during the test. Three command confirmations were observed, including the final Stop after forwarding recovery. Retained command rejection and invalid payload handling are covered by software tests.

## Forwarding disabled

Forwarding was disabled for 40 seconds. Upstream sent/received counters did not increase; five device datagrams were blocked from forwarding and 126 Ethernet telemetry records were received. Fresh local telemetry continued to report Stopped.

The HTTP Fast request returned 409. The MQTT Fast request emitted `local_command_rejected`. Home Assistant marked the charging-mode select unavailable. This confirms the current limitation: **independent offline mode control does not work**. This was a relay-forwarding test, not an all-protocol internet isolation test or an offline reboot test.

Forwarding was restored, the session became ready again, and a subsequent Stop request was confirmed. The charger was left stopped.

## Issues exposed and fixed

An initial run exposed loss of command-counter continuity: ordinary replies could displace older commands from the bounded startup candidate list. Counters now persist atomically outside the traffic journal, scoped to the session key. This alone did not resolve failed live requests.

Commands sent between charger polls could remain unconfirmed. A request sent immediately after a poll succeeded. The runtime now waits for the next validated device datagram before sending a queued request. Queue and confirmation stages each time out after 30 seconds; disabling forwarding cancels queued commands. These timing observations establish the tested behavior, not a complete description of firmware receive timing.

All 40 software tests passed, including queue dispatch, cancellation, expiration, counter persistence and storage failure. GitHub image build/test/publish passed. The deployment is pinned to the tested image digest.
